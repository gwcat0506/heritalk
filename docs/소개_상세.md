# heritalk(걷는 시간) — 도보 여행 역사 AI 가이드

> KCISA 제4회 문화체육관광 AI·데이터 활용 공모전 출품작
> 부문: 문화데이터 활용 / 제품·서비스 · 형태: 설치 없이 작동하는 반응형 웹앱(라이브 URL 데모)

## 1. 제안 아이디어 구성

박물관·미술관·유적지를 찾는 사람은 많지만, **"한 점의 시간(작품·유물·빈 터)"을 살아 있는 맥락으로 경험하기는 어렵다.** 벽 라벨 한 줄과 단방향 QR 오디오로는 "왜 중요한지"를 알 수 없고, 도슨트는 시간·예약·언어에 묶여 있으며, 어디를 어떤 순서로 걸어 도느냐를 직접 검색·지도로 짜맞춰야 한다. 한국사DB·박물관 도록 같은 1차 사료는 개방돼 있어도 일반인이 소화하기 어렵다.

**heritalk은 거점(박물관·미술관·유적지)을 *걸으면서*, *내 관심사대로*, *신뢰할 수 있는 깊이로* 안내받는 경험**을 제안한다. 설치 없이 웹 브라우저에서 즉시 작동하며, 제품을 정의하는 두 축은 다음과 같다.

1. **동선 에이전트** — 내 위치 한 번으로 실제 걸을 수 있는 도보 코스를 자동 생성(방문 순서 최적화 + 실제 보행 경로·시간).
2. **AI 채팅 도슨트** — 거점·작품 앞에서 자연어로 묻고 **국가유산청 공식 설명에 근거한 출처 인용 답변**을 받는다. 코스를 걸을 때는 전체를 "하나로 이어지는 이야기"로 엮어 정류지마다 해설을 들려준다.

공공에 흩어진 문화유산·관광·사료 데이터를 RAG와 동선 엔진으로 통합해, **"흩어진 POI"를 "걸을 수 있는 코스"로, "벽 라벨 한 줄"을 "출처 달린 깊은 해설"로** 바꾸는 것이 핵심이다.

## 2. 서비스 세부 흐름 (사용자 여정)

| 단계 | 화면 | 동작 |
|---|---|---|
| **① 발견** | 홈 (`/`) | 지도 히어로 + "주변 코스 추천" 단일 CTA. 위치는 옵트인 — 허용하면 내 위치, 아니면 서울 도심 기준. 사진 있는 가까운 거점을 보여주는 발견 레일 제공 |
| **② 코스 생성** | 코스 (`/course`) | 주변에서 거점 고르기 / swipe 선택 → 방문 순서 최적화 + 실제 도보 경로·예상 시간 계산 |
| **③ 결과·지도** | 코스 결과 (`/course/result`), 지도 (`/map`) | Kakao 지도에 핀·폴리라인 표시. 거점 목록과 누적 거리·시간 |
| **④ 투어·해설** | 투어 (`/docent`, `/heritage-live`) | 코스를 걸으며 정류지에 다가갈 때마다 이야기 토막 해설. 거점·작품 앞에서 자연어 Q&A |
| **⑤ 거점 상세** | `/place/[id]` | 국가유산청 라이브 상세(시대·지정종류·설명·이미지) + 채팅 도슨트 진입 |
| **⑥ 저장·회상** | 저장 (`/saved`), 마이 (`/mypage`) | 코스·거점 북마크, 언어·난이도·관심사 설정 |

## 3. 핵심 기능

### F1. 동선 에이전트 (코스 생성)
- **방문 순서 최적화** — nearest-neighbor 알고리즘으로 시작점에서 가장 가까운 거점을 순차 연결(`lib/routeEngine.ts`).
- **실제 보행 경로·시간** — 구간마다 **TMap 보행자 경로 API**로 실제 도보 경로(폴리라인)와 소요 시간을 계산하고 누적 집계. 구간 실패 시 직선거리×1.3 ÷ 1.3 m/s 폴백으로 코스가 끊기지 않음.
- **위치 기반 추천** — 내 위치(없으면 서울 도심) 반경 1.5km 내 거점을 추리되, 사진 있는 거점을 우선해 첫인상을 살림(`lib/recommendCourse.ts`).

### F2. AI 채팅 도슨트 (사료 grounding)
- **출처 인용 답변** — 응답 첫 줄에 `citations`(국가유산청 공식 설명) 메타를 실어 보내고, 이후 답변 토큰을 **스트리밍**. 자료에 근거하며 확실치 않으면 단정하지 않도록(환각 차단) 시스템 지침으로 강제.
- **거점 모드 / 일반 모드** — `placeId`가 있으면 해당 거점 공식 설명문을 grounding 컨텍스트로 사용, 없으면 한국 역사·유산 전반에 대한 일반 도슨트로 동작.
- **개인화** — 난이도(어린이·일반·전문가), 언어(한/영), 관심사를 프롬프트에 반영해 깊이·말투·강조점을 맞춤.

### F3. 투어 스토리텔링 (이어지는 이야기)
- 코스 전체를 관통하는 **하나의 큰 줄기**(공통 시대·인물·사건·주제)를 자료에서 찾아, intro → 정류지별 해설 토막(장소당 3~5개) → outro로 엮음(`generateTourStory`).
- 각 토막은 "곧 ~가 보입니다"처럼 **다가가는 시점**에 들려주는 1~2문장의 완결된 조각. 앞 장소와의 연결 → 깊은 본론 → 전체 줄기 속 의미로 흐르고, 마지막 토막은 다음 장소로 다리를 놓음.
- 경로 위 누적 거리를 정류지에 매핑해(`lib/tour/route.ts`) 실제 걷는 진행과 해설을 동기화.

### F4. 거점 카탈로그 & 라이브 데이터
- **국가유산청(KHS) OpenAPI 라이브 조회** — 서울(ccbaCtcd=11)의 국보·보물·사적·명승·천연기념물·시도유형·시도기념물을 무인증으로 조회, 좌표·시대·지정종류·이미지·설명을 POI 형상으로 정규화(`lib/khs.ts`, `lib/places.ts`).
- **정적 시드 116곳** — 역사박물관 42 + 국가지정 사적 74의 실데이터(좌표·이미지·시대)로 키 없이도 목록·추천·코스가 동작.

### F5. 회상·아카이브 (경량)
- 코스·거점 저장(Zustand + localStorage), 방문 일지·공유, 언어·난이도·관심사 등 사용자 취향 보관(Supabase profiles).

## 4. 특징 (차별점)

- **설치 0 · 즉시 체험** — 네이티브 앱이 아닌 반응형 웹앱. 라이브 URL 하나로 누구나 즉시 사용.
- **박물관·미술관·유적지를 동등하게** — POI 나열·평점 중심 관광앱과 달리, 거점↔거점·거점↔외부를 잇는 동선 엔진으로 깊이를 제공.
- **출처 기반 신뢰성** — 모든 거점 해설이 국가유산청 공식 설명에 grounding되고 답변에 출처가 함께 노출 → 환각 억제.
- **점진적 향상(graceful degradation)** — 키가 없어도 핵심이 동작: 지도 키 없으면 목록, TMap 키 없으면 직선거리 폴백, LLM 키 없으면 거점 요약 폴백.
- **다국어·다난이도 보편화** — 한/영, 어린이~전문가 난이도로 외국인·재외동포·초심자까지 문화 향유를 보편화.
- **이종 공공데이터 결합** — 국가유산청 GIS·설명 × TMap 보행 경로 × Kakao 지도 × 사료 RAG.

## 5. 핵심 기술 스택

| 영역 | 기술 |
|---|---|
| **프런트·배포** | Next.js 15(App Router) · TypeScript · Tailwind CSS · Zustand · Vercel |
| **백엔드·DB** | Supabase (PostgreSQL + **PostGIS** 공간검색 + **pgvector** 벡터 RAG) · Supabase Auth |
| **지도·경로** | **Kakao 지도**(핀·폴리라인 표시) + **TMap 보행자 경로 API**(실제 도보 경로·시간) |
| **LLM·임베딩** | **Google Gemini 2.5 Flash**(채팅·투어 스토리텔링, 스트리밍) + **text-embedding-004**(768차원, RAG 임베딩) |
| **데이터 소스** | 국가유산청(KHS) OpenAPI(서울 라이브) · 정적 시드 116곳 · 사료 시드(pgvector 적재) |
| **패키지 매니저** | bun (TypeScript 네이티브 실행 → 시드 스크립트에 별도 러너 불필요) |

**아키텍처 특징**
- **서버 전용 키 보호** — TMap·Gemini 키는 API Route(`/api/route/build`, `/api/docent`, `/api/tour`)에서만 사용, 클라이언트 노출 없음.
- **스트리밍 응답 계약** — 도슨트 API는 `text/plain` 스트림으로 첫 줄 메타(citations) + 토큰 스트림을 흘려 체감 지연 최소화.
- **토이 → 웹 이식** — 검증된 SwiftUI 동선 PoC를 이식: RouteEngine→`routeEngine.ts`, MapKit→Kakao, MKDirections→TMap, CoreLocation→Geolocation.

## 6. 데이터 흐름 (요약)

```
[국가유산청 OpenAPI] ──라이브 조회──▶ lib/khs.ts ──정규화(POI)──▶ /api/heritage/seoul
                                                                      │
[정적 시드 116곳] ───────────────────────────────────────────────────┤
                                                                      ▼
                                                          홈 추천·코스 풀(buildWalkablePool)
                                                                      │
                                            거점 선택 ──▶ routeEngine(순서 최적화)
                                                                      │
                                              TMap 보행 경로 ◀────────┘
                                                                      ▼
                                              Kakao 지도(핀·폴리라인) + 누적 거리·시간
                                                                      │
                  거점/작품 앞 질문 ──▶ /api/docent ──grounding(국가유산청 설명)──▶ Gemini(스트리밍)
                                                                      │
                                                 출처 인용(citations) + 답변 토큰
```

## 7. 적용 시나리오 (페르소나)

| 페르소나 | 불편 | heritalk의 해결 |
|---|---|---|
| **주말 산책러** (2030) | 코스 짜기 번거롭고 맥락 없이 지나침 | "주변 코스 추천" 한 번 → 도보 코스 + 입장 시 핵심 거점 가이드 |
| **역사 답사 애호가** | 사료 흩어짐, 동선·해설 깊이 부족 | 전문가 난이도 + 국가유산청 출처 채팅 도슨트 + 이어지는 투어 스토리 |
| **인바운드 외국인·재외동포** | 영어 정보 단편적, 깊은 해설 부재 | 영어 채팅 가이드 + 거점↔외부 연결 동선 |
